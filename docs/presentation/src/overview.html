Executive summary

What YCT Exam Portal is, why it matters and where it stands today.

YCT Exam Portal is a web application that produces Yaba College of Technology's examination timetable automatically, free of clashes, with every class placed in a hall that can hold it and every student given a numbered seat. It then guides each student to the right hall on the day, using the phone in their pocket.

The challenge

Every semester the timetable has been built by hand in a spreadsheet: checking which courses clash, which halls are free and whether each class will fit, then pinning seat lists on noticeboards. It takes days, mistakes are hard to spot, and students crowd round printed sheets before setting off to find a building some have never visited.

The solution

The exams office keeps the academic structure and exam halls in one system; students register and choose their courses themselves. One click creates the exam slots, schedules every course without clashes, books halls and numbers every seat. After review the officer publishes, and each student sees their own timetable, with live walking directions to the hall.

Where it stands

The challenge

How the examination timetable has been produced until now, and what that costs.

Every semester, the Department of Computer Science prepared its examination timetable by hand in a spreadsheet. Staff collected the course list for every level, checked by eye which papers could not sit together, found out which halls were free, estimated whether each class would fit, typed seat lists and pinned them on a noticeboard. The work took days and had to be partly repeated whenever something changed.

Days of work

Every timetable assembled and re-checked by hand, each semester.

Clashes slip through

Two papers for the same class can land in the same slot unnoticed.

Halls overflow

Without exact numbers, a class can be sent to a hall that is too small.

Crowds and lost students

Students queue at noticeboards, then search for unfamiliar buildings.

3

The solution at a glance

One shared system for the exams office and every student, on any phone or computer.

YCT Exam Portal is a web application: it runs in any modern browser, on phones and computers, with nothing to install. It replaces the whole manual process in five steps.

  1. The exams office keeps the college's structure in the systemSchools → departments → programmes (ND / HND) → levels (ND 1, ND 2, HND 1, HND 2) → courses, plus every exam hall with its seating capacity and GPS location.
  2. Students register themselvesWith their matric number, department, programme and level. Then they tick the courses they are taking this semester.
  3. The officer clicks GenerateAfter choosing the first exam day and the length of the exam period, the system creates the time slots, places every course so that no level sits two papers at once, never schedules more exams in a slot than there are halls, books halls and gives every enrolled student a numbered seat. It then reports anything that needs attention.
  4. Review, then PublishThe officer checks the draft department by department, adjusts if needed and clicks Publish. Only then do students see it.
  5. Students open the portal on their phoneTheir next exam with a countdown, date, time, hall and seat, and a Navigate to Hall button that shows a live walking route from where they stand.

How it works

Architecture, security, data, the timetable engine and navigation, explained for a mixed audience.

6.1 Architecture

Everything a user does starts in the browser and passes through an access gateway before it reaches the application. The application's pages and its REST API share one codebase; the scheduling engine is a set of focused services; and all data lives in a managed PostgreSQL database on Supabase.

6.2 Security and access control

Access is checked at three independent points on every request, so each page and each action is only ever available to the people it is meant for.

Roles cannot be self-assigned

Roles live in protected account metadata that only the server can write, so nobody can promote themselves.

Students only see their own data

Students never send their own ID; the server identifies them from their sign-in, so they can only ever read and change their own records.

Passwords handled by Supabase

Sign-in is provided by Supabase Authentication; the application never stores passwords.

Row-level security on every table

The public key used by browsers cannot read the tables; only the server, with its private credentials, talks to the database.

Every input validated

Forms and API requests are checked with the same Zod rules in the browser and on the server.

Clean, unique matric numbers

Matric numbers are normalised (f/nd/24/3210001 → F/ND/24/3210001) and checked for duplicates regardless of letter case.

Admins can correct student records, reset a student's password or remove an account from the Students screen.

Seventeen tables hold the academic structure, the people, course registration, examinations, the campus map and one operational safeguard.

6.4 The timetable engine

When the officer clicks Generate, the engine turns courses, enrolments and halls into a complete draft timetable in nine steps. The officer chooses three inputs in the Generate dialog: the School ("All Schools" or one school), the Exam Start Date (next Monday by default) and the Exam Period (1 to 6 weeks, two weeks by default).

#StepWhat happens
1LockThe session is locked so two generations cannot run at the same time. A lock left by an interrupted run expires automatically after 10 minutes.
2Time slotsMonday to Friday, two papers a day (Morning 08:00-10:00 and Afternoon 12:00-14:00) for the whole exam period (2 weeks = 10 weekdays = 20 slots). Only slots inside the exam period are used.
3Load dataThe courses for the semester (the session name says First or Second), the active halls, every student's enrolments and the number of students at each level.
4HeadcountClass size is the number of students enrolled in the course; if nobody has enrolled yet, the number of students registered at that level. Courses with no students are skipped.
5Clash ruleEvery course is a node; two courses in the same level are joined by an edge, because the same students sit both. No level ever has two papers at once. This protects every student, including those still finishing enrolment.
6DSatur schedulingThe engine repeatedly takes the most constrained course, the one whose clashing courses already occupy the most different slots (ties decided by number of clashes, then class size, then a fixed order), and places it in the earliest slot that holds no clashing course and still has enough free hall space for the whole class. Halls already booked in that slot by another timetable (another school or session) are treated as unavailable.
7Halls and seatsWithin each slot the largest class chooses first and takes the smallest free hall that fits the whole class; a class too big for any single hall fills the largest free hall and continues in the next. A hall holds one course per slot. Seats are numbered 1, 2, 3… inside each hall, in matric-number order.
8SaveEverything is written in one all-or-nothing database transaction, as a Draft.
9Report"N courses scheduled", plus Unresolved (no clash-free slot left, so choose a longer exam period) and Hall Overflow (not enough hall space, so add halls or capacity) when needed. Generating again replaces the draft.
DSatur in plain English

Think of each time slot as a colour and each course as a dot; dots joined by a line must get different colours. DSatur ("degree of saturation") always colours next the dot that is hardest to place, the one already surrounded by the most colours, so difficult courses are placed while there is still room. Because ties are always decided in the same fixed order, the same input always produces the same timetable.

Worked example

Three levels (ND 1 with four courses, ND 2 with three and HND 1 with three) and two halls. The conflict graph on the left joins courses of the same level. On the right, each column is a time slot: no column ever holds two courses of the same level, and no column holds more than two exams, because there are only two halls.

Halls and seats

Once a course has its slot, it is given halls and every enrolled student receives a seat. Best fit keeps big halls free for big classes; a class larger than any hall is split across halls automatically.

6.5 Timetable lifecycle

A timetable is always created as a private Draft and becomes visible to students only when the officer publishes it.

  • Edit Slot (drafts only) moves one exam to another slot. The system checks for clashes and automatically re-assigns halls and seats in the new slot.
  • Publish All releases the timetable to students after checking that every scheduled course has a hall, every enrolled student has a seat, and every course with enrolled students is on the timetable.
  • Late registration: a student who enrols after the timetable has been generated is automatically given the next free seat in one of that course's halls, if there is room. Dropping a course before publication frees the seat, and a dropped course can be added again.
  • After publishing, students can no longer drop published courses. For bigger changes the officer uses Reset All, then generates and publishes again.
  • Seat Assignments lists every student's course, date, hall and seat, ready to share with invigilators.

6.6 Hall navigation

The Navigate tab lists every active exam hall with a small map preview, its code, description and coordinates. Opening a hall, or tapping Navigate to Hall on the timetable, shows a full-screen map with the hall (green pin), the student's live position from the phone's GPS (blue dot) and the walking route, with distance and time such as "850 m · 11 min walk".

  • The route updates as the student moves. If the route service cannot be reached, a straight line and an estimated walking time are shown instead.
  • Open in Google Maps hands off to Google Maps walking directions for turn-by-turn guidance.
  • Location is shared only with the student's permission, and browsers provide it over a secure (https) connection.
  • A campus map graph (navigation nodes and paths) with a Dijkstra shortest-path API, /api/navigation/path, is also available for campus-specific routing.

The Exams Office portal

A guided tour of the screens the exams office uses every semester.

The portal opens on the Dashboard. A sidebar lists Dashboard, Schools, Departments, Courses, Halls, Timetable and Students; the header shows the page name and a light/dark switch; the sidebar footer shows the signed-in email, role and Sign out. Ctrl/Cmd + B collapses the sidebar. Every list is a sortable table on computers and a set of cards on phones; deletions always ask for confirmation, and every action confirms success or explains an error.

The Timetable screen: the command centre

Choose a session, or create one with + ("YYYY/YYYY First Semester" or "Second Semester"). The Active / Inactive switch controls whether students can see the session; a session can also be deleted. The toolbar offers Generate, Publish All, Seat Assignments and Reset All; department tabs split the timetable for review, with columns Code, Title, Level, Date, Time, Halls and Status (Draft / Published) and an Edit Slot action on drafts.

When a run needs attention, the report names the courses concerned and the remedy: a longer exam period for Unresolved courses, more hall space for Hall Overflow. Once the timetable is published, Seat Assignments lists every student's course, date, hall and seat for invigilators.

The Student portal

Designed for the phone in every student's pocket, and just as good on a computer.

Students sign up at /register with their Full Name, Matric Number, Email, Department → Programme → Level and a password, and are signed in immediately. They then see Select Your Courses: the courses for their level and the current semester, all pre-ticked. They untick any electives they are not taking and tap Complete Enrollment (or Skip for now). On a computer the portal has a top bar (Timetable, Navigate, Courses, Profile, theme switch, Sign out); on a phone the same tabs sit in a bottom tab bar.

Timetable

The Timetable tab has a session selector and a progress bar ("2 / 6", "4 remaining"). The Up Next card shows a countdown (Today, Tomorrow or In N days), the seat number, course code and title, date, time, and the hall's name and code, with a Navigate to Hall button. Below are the Upcoming exams and a collapsible Completed list (an exam moves there once it has finished), ending with "All exams completed". Only published timetables appear. If a hall is shown before a seat number has been assigned, the student sees "Seat number not yet assigned: please contact the exams office".

Navigate

A directory of every active hall, and a full-screen map for each: the hall, the student's position and the walking route, with Open in Google Maps for turn-by-turn directions.

Courses and Profile

Courses lists the level's courses for the selected session's semester with Enroll and Drop (with confirmation); published courses show Locked, alongside the enrolled count and total credit units. The chosen session is remembered between Timetable and Courses. Profile shows the student's details, an emoji avatar, the light/dark switch and Sign out.

Running an exam period

The exams officer's checklist, from set-up to the last paper.

  1. Check the academic structureSchools, departments and courses are in place. Adding a department creates its ND and HND programmes and four levels automatically; courses can be imported in bulk from CSV.
  2. Confirm the hallsEvery hall in use has its real seating capacity and GPS coordinates and is marked Active. Halls no longer used are set to Inactive.
  3. Prepare the sessionOn the Timetable screen, create the session with + (e.g. "2025/2026 First Semester") and make it Active, so students can see it.
  4. Open student registrationStudents sign up at /register and choose their courses. The Students screen shows who has registered.
  5. GenerateWhen registration closes, click Generate and choose the School ("All Schools" or one), the Exam Start Date and the Exam Period.
  6. Read the report"N courses scheduled". If Unresolved courses are listed, choose a longer exam period; if Hall Overflow is listed, add halls or capacity. Then generate again.
  7. Review department by departmentUse the department tabs to check dates, times and halls. Edit Slot moves a single exam; clashes are checked and halls and seats re-assigned automatically.
  8. Publish AllThe system confirms that every course has a hall, every enrolled student has a seat and every course with students is scheduled. Students can then see their timetable.
  9. Share Seat AssignmentsThe list of every student's course, date, hall and seat is ready for invigilators.
  10. During the exam periodLate registrations receive the next free seat automatically when there is room. For bigger changes, use Reset All, then generate and publish again.
Tip

Keep only the current session Active, generate after registration has closed, and look through every department tab before publishing. The Exams Office Guide covers each step in detail.

The student journey

From creating an account to finding the right seat in the right hall.

  1. Create an accountAt /register: Full Name, Matric Number, Email, Department → Programme → Level, Password and Confirm Password, then Create account. The student is signed in straight away.
  2. Select Your CoursesThe courses for their level and the current semester appear, all ticked. They untick electives they are not taking and tap Complete Enrollment.
  3. Wait for publicationThe timetable appears on the Timetable tab as soon as the exams office publishes it, so there is nothing to check on a noticeboard.
  4. Check what is nextThe Up Next card shows the countdown, date, time, hall and seat; Upcoming lists the rest; finished papers move to Completed.
  5. Navigate to HallOn exam day, tap the button, allow location access, and follow the live walking route, or open it in Google Maps.
  6. Take the right seatSeat numbers start at 1 in each hall, so the student reads hall and seat together.
  7. Keep courses up to dateOn the Courses tab students enrol in or drop courses. Once a course's timetable is published it shows Locked and stays on their list; a late enrolment still receives a seat when there is room.
Help when it is needed

Forgotten passwords and corrections to a student's department or level are handled by the exams office, which can update records and reset passwords. The Student Guide answers the most common questions.

Deployment and operations

How the system is hosted, configured, checked and kept running.

Hosting

The application runs on Vercel; the production build runs prisma generate and next build. Live pilot: smart-exam-timetable.vercel.app.

Database

A Supabase project provides PostgreSQL and sign-in. Database migrations are applied with npm run db:migrate:prod.

GitHub Actions runs linting, type-checking, the automated unit tests and a production build on every change.

Appendix B: API reference

Every endpoint under /api, grouped by area.

All responses share one JSON shape: { success, data, message, errors? }. Who can call it: Public no sign-in needed · Signed in any role · Student · Admin exams officer or super admin · Setup secret. API calls made without signing in receive a clear "please sign in again" response, and calls with the wrong role are refused.

Appendix C: Glossary

Terms used in this document and in the app.

SessionAn academic session and semester, named like "2025/2026 First Semester". Each can be Active (visible to students) or Inactive.
SemesterFirst or Second. Every course belongs to one; the session name decides which courses are timetabled.
LevelA year group within a programme: ND 1, ND 2, HND 1 or HND 2. Courses and students belong to a level.
ProgrammeA diploma track within a department: National Diploma (ND) or Higher National Diploma (HND).
Time slotA date with a start and end time. The engine uses Morning 08:00 to 10:00 and Afternoon 12:00 to 14:00, Monday to Friday.
Timetable entryOne course's exam placed in a time slot for a session, with its halls; Draft or Published.
Draft / PublishedA Draft is visible to the exams office only; Published timetables are visible to students.
HeadcountThe class size used for seating: students enrolled in the course, or students registered at the level if nobody has enrolled yet.
Conflict graphA network in which each course is a point and courses of the same level are joined, meaning they cannot share a slot.
DSatur"Degree of saturation", a well-known graph-colouring algorithm that always places the most constrained course next. Each time slot is a colour.
Best fitGiving a class the smallest free hall that can seat all of it, keeping larger halls free for larger classes.
Hall OverflowA report list of courses for which there was not enough hall space; the remedy is to add halls or capacity and generate again.
UnresolvedA report list of courses for which no clash-free slot was left; the remedy is a longer exam period.
Matric numberA student's college registration number, e.g. F/ND/24/3210001, stored in capitals and unique regardless of letter case.
RLS (row-level security)A database feature that controls access to every table; here it keeps all tables closed to browsers, so only the server can read or write data.
APIApplication Programming Interface: the set of web addresses under /api that the screens use to read and change data.
